# Локальная подготовка разметки

Рабочая копия: `datathon2026_tumo-astana-ml`, ветка `ml`. Исходная копия проекта не изменяется.
Все видео, исходная Excel-таблица, подробные заметки и разметка остаются в `data/`, которая исключена из Git. Не отправляйте кадры, видео и описания сцен в облачные инструменты.

## Что уже подготовлено

```bash
.venv/bin/python -m scripts.prepare_data ../open.zip --output data/real
```

Команда запускается один раз: существующая папка намеренно не перезаписывается.
В `data/real/manifest.draft.json` находятся 42 записи, исходные значения Excel в `source`, метаданные и SHA-256. `review.assignee` распределяет видео по 14 на каждого из трёх разметчиков. Имена `labeler_1..3` условные: назначьте людей сами. Две лишние копии точных дубликатов требуют общего split с оригиналами.

## Что заполняют люди

1. Скопируйте черновик в `data/real/manifest.json` **в той же папке**: пути к видео относительны manifest.
2. Просматривайте видео обычным локальным плеером. Для каждого запишите `group` по сессии, камере и участникам. Одинаковый `suggested_exact_group` означает точные копии; объединяйте также связанные, но не идентичные записи. После проверки установите `group_reviewed: true`.
3. До обучения согласуйте `split`: `train`, `val`, `test`, примерно 60/20/20. Все записи одной группы и все точные копии должны находиться в одном split. Сохраните отдельную неизменяемую копию manifest для воспроизводимости. Не используйте test для настройки.
4. Укажите `segments`: `{"start": 1.0, "end": 3.0, "label": "class_id"}`. Конец интервала исключается. Явно размечайте нормальные интервалы как `normal`. Вне размеченных интервалов кадры игнорируются. Допустимы перекрытия разных событий, но нормальный интервал не может пересекаться с событием.
5. В `events` укажите **все** события: `{"time": 2.0, "label": "class_id"}`. Время — секунды от начала видео; оно должно соответствовать реальному кадру. `events: []` означает проверенное отсутствие событий, а не отсутствие разметки. Устанавливайте `events_reviewed: true` лишь после полного просмотра. Зафиксируйте неоднозначность в `review.uncertain` и локальных `review.notes`.
6. Не подменяйте класс бинарной меткой Excel и не превращайте её единственную отметку времени в интервал события. Если проверенные события противоречат исходной бинарной метке, разрешите расхождение локально до обучения/оценки. Импортёр сохраняет исходные значения без изменений.

Поддерживаемые train-классы должны быть включены и проверены в `rules/catalog.json`. Сейчас доступны `cashier_leaves` и `previous_cash_exposed`; это гипотезы, а не подтверждённые классы реальных видео. Не выбирайте их только ради совместимости. Сначала определите таксономию по train и проверьте нормативное основание. Неподдерживаемые события holdout допускаются и учитываются как пропуски. `demo_absent` запрещён для реальных данных.

## Проверка и запуск

```bash
.venv/bin/python -m scripts.validate_manifest data/real/manifest.json --purpose train
.venv/bin/python -m ml.train data/real/manifest.json --output models/reference.npz
.venv/bin/python -m scripts.validate_manifest data/real/manifest.json --purpose evaluate
.venv/bin/python -m scripts.evaluate data/real/manifest.json --split val --output runtime/validation.json
```

Не запускайте оценку `test`, пока модель и настройки не зафиксированы. Оценщик использует внутренний допуск 3 секунды, а не официальный критерий. Ошибки обработки считаются пропусками всех ожидаемых событий; отчёт успешных видео выводится отдельно.
