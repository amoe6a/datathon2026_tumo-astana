## Качество на реальных данных

Основные показатели считаются по уникальным видео, без повторного учёта точных копий. Это бинарная оценка по исходным меткам организатора, а не точность типов событий.

| Кандидат и выборка | Уникальных видео | TP | TN | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Исходный appearance/motion, validation | 7 | 1 | 0 | 4 | 2 | 0,200 | 0,333 | 0,250 |
| Вычитание медианного фона, validation | 7 | 3 | 1 | 3 | 0 | 0,500 | 1,000 | 0,667 |
| Видео-признаки, выбор настроек только train OOF, validation | 7 | 3 | 1 | 3 | 0 | 0,500 | 1,000 | 0,667 |
| Bonsai, validation | 7 | 1 | 3 | 1 | 2 | 0,500 | 0,333 | 0,400 |
| **Зафиксированный CPU baseline, финальный test** | **7** | **3** | **0** | **3** | **1** | **0,500** | **0,750** | **0,600** |

На test CPU baseline дал ложную тревогу на всех трёх нормальных видео. Bonsai лучше подавляет ложные тревоги на validation, но пропускает 2 из 3 положительных видео. Его отметки не совпали ни с одной из 4 исходных отметок положительных validation-файлов в пределах внутреннего допуска 3 с. У CPU baseline на test совпали 2 из 4 отметок, медианная ошибка совпавших — 1,0 с.

Исходная таблица содержит бинарные метки и отдельные отметки времени, без полного списка типов/интервалов. У одной положительной пары одинаковых видео исходные отметки различаются. **Event precision/F1 и точность семантических типов не измерены.** В слабом оценщике неоднозначные поля event F1 заменены честным organizer-anchor recall. Старые локальные отчёты с single-anchor proxy нельзя трактовать как настоящую event F1.

Полные агрегированные числа: [reports/ml-quality.json](../reports/ml-quality.json). Предыдущее F1=0,727 было посчитано по файлам с дубликатом; основным validation-результатом CPU остаётся 0,667.

## Как выбирали и что зафиксировано

42 файла, 40 уникальных видео; 22 положительных и 20 отрицательных файлов. Заморожено 26 train / 8 validation / 8 test по файлам, или 26/7/7 уникальных видео. SHA-256 и одинаковые H.264-потоки не пересекают split. Съёмочные сессии и близкие записи независимо не проверены: обобщение на новую камеру не доказано.

Слабый CPU baseline обучался только на нормальных исходных видео и окнах вокруг исходной отметки положительных видео; остальные кадры положительного видео не объявлялись нормальными. После сравнения 16 заранее заданных validation-конфигураций выбран temporal_delta, окно ±2 с, C=0,03, порог 0,6; 1143 обучающих кадра. Альтернативный видео-классификатор выбрал параметры 4-fold OOF только внутри train и улучшения не дал.

Перед единственным финальным test сохранены конфигурация, SHA-256 весов, split и кода: локальная `runtime/weak-baseline-delta/selection.freeze.json`. `final-test.started` блокирует повторный test и дальнейший подбор в этой папке. После результата test параметры не менялись. Веса бинарных экспериментов намеренно отвергаются нормативным API: проверенных семантических классов у них нет. Ни Bonsai, ни альтернативный CPU-классификатор на test не оценивались.

## Реальный Bonsai и производительность

Bonsai действительно запущен локально. Основной GGUF и Q8-проектор сверены с SHA-256 издателя ревизии `b072e1d3b35a0a630cece372c2127528e0994386`. Официальный PTQ runtime собран из commit `e3de715222b2667c54a267441159a5729f11155e` с CUDA 13.4, GCC/G++ 14, архитектурой 89. При восстановлении исходников проверялись git blob SHA. Недостающий ui-assets.cmake восстановлен, сборка llama-server завершилась успешно.

Рабочая конфигурация: [configs/bonsai.json](../configs/bonsai.json), весь языковой backbone в GPU, проектор в CPU, контекст 4096, один запрос, окна 32 с / шаг 24 с / 0,5 fps, изображения до 448 px, 64–128 визуальных токенов. На двух train-видео общий прогон сократился с 165,64 до 35,23 с после совместного изменения GPU offload и временной выборки. Это не раздельная абляция этих настроек; положительный train-пример остался пропущен.

Вариант [configs/bonsai-detail.json](../configs/bonsai-detail.json) сохраняет больше деталей исходного изображения, использует 256 визуальных токенов и 0,25 fps. На той же train-паре: 40,84 с, положительный пример снова пропущен. Он отклонён на train, без дополнительного подбора по validation/test. Первые два обращения были отправлены до готовности сервера и завершились ошибкой соединения; затем оба успешно повторены с той же конфигурацией. В auto_annotate исправлено возобновление: неуспешный cache больше не считается завершённой обработкой.

Холодный полный API-цикл в отдельном Linux network namespace на длинном train-видео 142,533 с: **139,73 с**, из них API после готовности сервера 137,16 с. Пик native VRAM 6 268 387 328 байт (5,84 ГиБ), native RSS 6 505 807 872 байт (6,06 ГиБ); RSS API 63 МиБ. Это настоящая модель, настоящий upload/job/worker и сеть только lo, без внешних маршрутов. Предсказанный вердикт в этом benchmark не означает подтверждение его правильности.

Три холодных запуска на самом длинном validation-видео 72,700 с: **75.91 / 73.13 / 72.75 с** полного цикла. Все три завершились done, каждый вернул 3 JPEG к предложенному событию. Пик native VRAM 5.84 ГиБ, native RSS 6.06 ГиБ. Сеть в каждом запуске: только lo, внешних маршрутов нет. Это проверка стабильности API и генерации доказательств, а не подтверждение правильности события.

Для слабого CPU baseline три новых процесса на train-видео 142,533 с заняли 1,813 / 1,855 / 1,855 с; максимум RSS 596 МиБ. Это не семантический и не API-замер. Файловый кеш ОС не сбрасывался во всех cold benchmark. RAM-пики отдельных процессов нельзя складывать и выдавать за измеренный общий пик всей системы.

## Разметка и незавершённая работа

Локальный `data/real/manifest.pseudo.bonsai.json` содержит машинные предложения для 10 файлов (2 train и 8 validation), 3 предложенных события с учётом повторной копии. Для 24 train-файлов предсказаний в этом черновике нет, 8 test-файлов исключены из экспорта. Все предложения помечены unreviewed, лежат в proposed_events, не превращаются в events/normal intervals и не допускаются как готовая обучающая разметка. Скрипт `scripts.export_pseudo_labels` сохраняет исходные бинарные метки, не читает test-предсказания и отказывается перезаписывать человеческую разметку.

Полная независимая разметка классов, интервалов, явных нормальных участков и групп съёмки не выполнена. Успешный автоматический ответ не считался независимой ground truth; массовая генерация меток слабым учителем не выдается за решение этой проблемы. Семантический reference на реальных проверенных интервалах не обучен.

Qwen `78448d793a7eb2f7a987a1da76d464384aa1becd`: processor проверен на синтетических изображениях, большие веса не загружены полностью; реального inference/качества нет. Лимит 45 минут настройки кандидатов ранее превышен; это отклонение от плана, а не успешная проверка Qwen.

Bonsai API пока экспериментальный: `scripts.serve_bonsai` сохраняет существующий контракт, но основной Settings.from_env и управление жизненным циклом native-процесса остаются задачей backend-владельца. Поддерживаемые правила остались исходными cashier_leaves и previous_cash_exposed; их покрытие реальных нарушений независимо не подтверждено. Готовый релиз не объявляется.

## Код и проверки

- Подготовка ZIP/XLSX, SHA-256, полное декодирование 42/42; сохранение последнего кадра, максимальный конечный зазор 0,034 с.
- Проверка manifest и frozen split: интервалы, классы, утечки, потерянные строки, неоднозначные нормальные участки; отсутствие reviewed-флагов не скрывается.
- Многометочное обучение, корректный учёт ошибок как пропусков и однозначное сопоставление событий.
- Локальные Qwen/Bonsai-сессии, контроль обрезанного JSON и неизвестных rule ID, настраиваемые временные окна и разрешение.
- Локальная псевдоразметка, проверка сигнатуры кода/конфигурации, экспорт непроверенных предложений, отдельные CPU/real API benchmark.
- **68 passed за 24,19 с**, одно предупреждение Starlette TestClient/httpx. Синтетические HTTP/API-проверки подтверждают контракт, а не точность распознавания. Real API cold runs отдельно описаны выше.

Базовая .venv использует Python 3.11.15. Отдельная .venv-inference: Python 3.14.7, torch 2.14.0+cu130, torchvision 0.29.1+cu130, transformers 5.17.0; CUDA-операция проверена. Эта среда создана копированием сторонних пакетов другой локальной среды без её изменения. Исходно предложенная установка torch/cu126 сорвалась из-за сети; shared requirements не менялись. Окружения и их freeze остаются локальными.

Один обзор реальных кадров был открыт coding assistant до повторного прочтения ограничений кейса; пользователю сообщено, дальнейший просмотр прекращён. Это отклонение от требования локальности. Нельзя заявлять, что вся подготовка целиком выполнялась без такой передачи. Эти кадры не считались ручной разметкой. Все последующие видеозапросы шли в локальную модель, настоящий offline API дополнительно проверен на уровне сети.
