# ML handoff — 17 октября 2026

Ветка: `codex/ml-local-evaluation`. Работа выполнена в отдельной копии проекта. `app/`, frontend, общий список зависимостей и каталог правил не изменялись. Это промежуточный результат: пригодная к соревнованию семантическая модель пока не получена.

## Что сделано

- Импорт ZIP/XLSX через `scripts.prepare_data`: исходные бинарные метки и отметки времени сохранены без выдуманных классов. 42 файла, 22 положительных и 20 отрицательных; 40 уникальных видео, две лишние точные копии. Полное декодирование 42/42, 2948 кадров при 2 fps, максимальный конечный зазор 0,034 с.
- `ml.manifest` и `scripts.validate_manifest`: интервалы, SHA-256, группы и утечки между всеми split, явные нормальные интервалы, полнота оценочной разметки. Черновой manifest намеренно не выдаётся за готовую семантическую разметку.
- `ml.train`: независимые бинарные классификаторы сохраняют перекрывающиеся события; прежний NPZ поддерживается. `ml.engine` отвергает слабые бинарные веса при нормативном анализе.
- `scripts.evaluate`: однозначное сопоставление событий с минимальной временной ошибкой, сбои учитываются как пропуски ожидаемых событий. Неуспешный отрицательный ролик не становится TN. Допуск 3 с — внутренний, не официальный.
- `ml.video`: сохранение последнего реального кадра, проверка немонотонных timestamps и неполного декодирования. Проверка количества кадров консервативна: может отвергать ролики с неверными метаданными.
- `ml.qwen`: повторное использование сессии, контроль визуальных токенов, сохранение временного покрытия; обрезанная генерация и неверные события отклоняются.
- `ml.bonsai`: отдельный адаптер с локальным loopback endpoint, запрещёнными redirect/proxy и строгим разбором результата. `scripts.serve_bonsai` использует существующий API-контракт; основной `Settings.from_env` пока не поддерживает bonsai. Постоянная интеграция и управление процессом остаются backend-задачей.
- `scripts.auto_annotate`: локальная псевдоразметка, приватные ответы остаются в data/, исходные бинарные метки не передаются модели в prompt. Псевдометки явно не считаются человеческой проверкой. Test требует зафиксированной сигнатуры конфигурации и inference-кода.
- `scripts.evaluate_source_labels`: бинарные метрики на уникальных видео и совпадение исходных временных отметок; метрики файлов с дубликатами выводятся отдельно.
- `scripts.download_model`: закреплённая ревизия и локальный манифест SHA-256. `scripts.benchmark_weak`: отдельные холодные CPU-процессы с запретом внешних Python-соединений.

## Измеренное качество

Это предварительный **слабый бинарный CPU baseline**, а не Qwen/Bonsai и не подтверждённое качество типов событий. В положительных train-видео используются только окна возле исходной отметки; остальные кадры положительного видео не объявляются нормальными.

Фиксированное разделение: 26 train / 8 validation / 8 test по файлам. В validation 7 уникальных видео: 3 положительных, 4 отрицательных. Точные дубликаты и идентичные H.264-потоки не пересекают split. Сессии и близкие записи независимо ещё не проверены, поэтому обобщение на новые камеры не доказано.

| Validation, уникальные видео | TP | TN | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Исходные appearance/motion признаки | 1 | 0 | 4 | 2 | 0,200 | 0,333 | 0,250 |
| Вычитание медианного фона ролика | 3 | 1 | 3 | 0 | 0,500 | 1,000 | 0,667 |

Улучшенный вариант даёт ложную тревогу на 3 из 4 нормальных уникальных видео. **Качество пока неудовлетворительное.** Параметры выбраны на validation среди 16 заранее заданных конфигураций: окно ±2 с, C=0,03, порог 0,6; 1143 обучающих кадра. Ранее F1=0,727 был рассчитан по 8 файлам с повторным учётом дубликата; основным результатом считать F1=0,667 по 7 уникальным видео.

Совпали 2 из 4 исходных временных отметок положительных файлов в пределах 3 с; медианная ошибка совпавших отметок 0,5 с. У одной положительной пары дубликатов исходные отметки времени различаются. Отметки не образуют полного списка событий: поля event F1 в раннем локальном weak-отчёте являются single-anchor proxy, их нельзя выдавать за настоящую event F1 или точность типов.

На длинном train-видео 142,533 с три новых CPU-процесса заняли 1,813 / 1,855 / 1,855 с целиком с запуском Python; максимум RSS 625 131 520 байт (596 МиБ), 286 кадров. Disk cache не сбрасывался. Это не GPU-замер и не полный API-цикл.

## Окружение и незавершённые кандидаты

Основная `.venv`: Python 3.11.15, CPU-зависимости из requirements.txt. Отдельная `.venv-inference` создана копированием установленных сторонних пакетов другой локальной среды без изменения её файлов; проверены Python 3.14.7, torch 2.14.0+cu130, torchvision 0.29.1+cu130, transformers 5.17.0, accelerate 1.10.1. Реальное CUDA-матричное умножение выполнено с конечными значениями. Эта среда отличается от исходно предложенной torch 2.8/cu126; установка последней сорвалась из-за сетевых ошибок. Общие requirements не менялись; локальные freeze находятся в runtime/.

Qwen: `Qwen/Qwen3-VL-2B-Instruct`, ревизия `78448d793a7eb2f7a987a1da76d464384aa1becd`. Конфигурация и processor проверены на синтетических изображениях; большие веса загружены не полностью, реального inference нет.

Bonsai: `prism-ml/Ternary-Bonsai-2-27B-gguf`, ревизия `b072e1d3b35a0a630cece372c2127528e0994386`. Основной GGUF 5 946 648 928 байт проверен по SHA-256 издателя. Проектор Q8 ещё не готов. Runtime закреплён на `e3de715222b2667c54a267441159a5729f11155e` (release `prism-b10777-e3de715`); исходники загружены с проверкой git blob SHA. Сборка CUDA началась, но ещё не завершена: обнаружен отсутствующий вспомогательный `scripts/ui-assets.cmake`, восстановление и успешная итоговая сборка не подтверждены. Наличие скачанных исходников и основного GGUF не означает работоспособность модели.

Длительная настройка кандидатов превысила исходный лимит 45 минут. Это отклонение от плана; Qwen/Bonsai пока нельзя считать успешно проверенными кандидатами.

## Проверки и ограничения

Синтетический Bonsai HTTP stub прошёл через настоящий POST/GET API и отдельный worker: известный rule ID даёт JPEG, неизвестный — failed без чистого вердикта. Это проверка кода, не модели. Полный `.venv/bin/python -m pytest tests -q` перед коммитом: **62 passed за 19,49 с**, одно предупреждение Starlette о TestClient/httpx. `git diff --check` пройден.

Синтетические offline-сценарии выполнены с запретом соединений. Дополнительно проверен network namespace с единственным lo и без внешних маршрутов; CUDA-операция работает внутри него. Полный offline-анализ реальной видеомоделью ещё не выполнялся.

Один обзор реальных кадров был открыт инструментом coding assistant до повторного прочтения ограничений кейса. Пользователю сообщено, дальнейший просмотр прекращён; это отклонение от требования локальности. Эти кадры не считаются независимой ручной разметкой. Нельзя заявлять, что вся подготовка целиком прошла без передачи кадров ассистенту. Дальнейшая псевдоразметка подготовлена для локального выполнения.

Приватные видео, manifest, предсказания, веса, окружения и runtime исключены из Git. Агрегированные числа выше приведены без кадров и описаний наблюдений. Включённые правила остаются исходными: `cashier_leaves`, `previous_cash_exposed`; применимость к train ещё не подтверждена независимой разметкой.

## Команды для продолжения

```bash
# Базовые проверки кода, без реальных видеомоделей
.venv/bin/python -m pytest tests -q

# Импорт при наличии локального архива; существующий output не перезаписывается
.venv/bin/python -m scripts.prepare_data /path/to/open.zip --output data/real

# Предварительный бинарный эксперимент, не нормативный анализ
.venv/bin/python -m scripts.weak_baseline data/real/manifest.draft.json --output runtime/weak-baseline-delta --variant temporal_delta

# После полной независимой разметки
.venv/bin/python -m scripts.validate_manifest data/real/manifest.json --purpose train
.venv/bin/python -m ml.train data/real/manifest.json --output models/reference.npz
.venv/bin/python -m scripts.validate_manifest data/real/manifest.json --purpose evaluate

# После загрузки весов Qwen; это пока не подтверждённый успешный запуск
.venv-inference/bin/python -m scripts.auto_annotate data/real/manifest.draft.json --smoke-pair
```

Локальные пути и split-файлы из data/, models/, runtime/ не передаются этой веткой. Для воспроизведения нужны исходный архив, импорт и подготовка окружений; семантическая разметка пока отсутствует.
